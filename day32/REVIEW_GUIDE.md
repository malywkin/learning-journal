# Правила проекта для AI-ревью (learning-journal)

Это «брендбук», который робот-ревьюер кладёт перед глазами, когда смотрит на изменения
в PR. Правила — из наших же договорённостей по курсу (корневой и доменный `CLAUDE.md`,
выводы прошлых дней). Робот сверяет правку с этим списком и пишет замечания.

## Безопасность (жёсткие правила — за нарушение сразу замечание)
- **Секреты никогда не в коде и не в коммите.** Ключи API, токены (`OPENROUTER_API_KEY`,
  `DEEPSEEK_API_KEY`, токены Telegram) — только из окружения / `.env`. Хардкод ключа,
  пароля, токена прямо в `.py`/`.yml` — красный флаг.
- `.env` и любые реальные секреты не коммитим (должны быть в `.gitignore`).
- Не коммитим тяжёлое и приватное: видео (`.mov`, `.mp4`), собранные индексы (`.db`),
  корпуса книг, `__pycache__`.

## Надёжность кода
- **Запись файлов — атомарно** (пиши во временный файл + `os.replace`), иначе падение
  посреди записи побьёт файл. Это наш вывод Дня 7 — откат к прямой записи в рабочий файл
  считается регрессом.
- Внешние вызовы (LLM, сеть) — с обработкой ошибок: **retry → fallback → не ронять**
  приложение. Голый вызов без таймаута и без запасного пути — замечание (наш §14).
- У клиента к модели задаём `timeout=` (иначе зависание вешает весь прогон).

## Контракт с моделью
- Структурный ответ берём через `response_format={"type":"json_object"}` + шаблон в
  промпте + разбор кодом. Строгий `json_schema` провайдеры не держат — не использовать
  (наша грабля Дня 24).

## Соглашения курса
- Папки дней — с нулём: `day01`…`day35`. Главный файл решения — `taskN.py`.
- Секреты — в `.env` (в `Tasks/.gitignore`).
- Код на Python: минимальный, читаемый, с короткими комментариями по-русски.
- **README в `Tasks/dayNN` не создаём и не коммитим.**

## Как писать замечание
- Тон — рекомендация, не приказ. Робот советует, финальное слово за человеком.
- Не спамить: сводное ревью, а не россыпь придирок. Стиль/форматирование — только если
  меняет смысл.
- Если правка хорошая — так и сказать (короткая похвала уместна).
