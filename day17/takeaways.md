# День 17 — свой MCP-сервер: выжимка

Тема недели 4 — MCP. День 16 был про КЛИЕНТА к чужому серверу, День 17 — про СВОЙ
сервер + агента, который реально зовёт инструмент. Формат сессии: код пишет Claude,
ученик разбирает «что под капотом». Сквозная метафора, которая зашла, — **ресторан**.

## Хребет темы (одним взглядом)
- **MCP = разъём для ИИ, у него две стороны.** Сервер — это «ресторан» (у него есть
  что предложить). Клиент — «посетитель», который заходит и заказывает. День 16 — мы
  были посетителем в чужом ресторане (читали меню). День 17 — открыли свой ресторан
  и сами заказываем.
- **Инструмент (tool) = блюдо в меню.** Собирается из трёх частей: имя (чтобы заказать),
  что в него вписать (**schema**) и что он возвращает (результат). Это ровно три пункта
  задания: регистрация / описание входных параметров / возврат результата.
- **Schema рождается сама.** Пишешь обычную функцию, помечаешь поля типами — сервер сам
  собирает из неё анкету (schema) для модели. Руками JSON-схему не пишешь.
- **Голова и руки.** Модель — голова: сама выбирает блюдо под живую просьбу человека
  (никто не приказывает «возьми это»). Агент-код — руки: несёт заказ на кухню
  (`tools/call`), забирает тарелку, отдаёт модели. Модель сама в базу не лезет.
- **Read/write + человек-в-цикле.** На каждом блюде ярлык: «только смотрит» или «меняет
  данные» (**annotations**). На «меняет» агент тормозит и спрашивает живого человека.
  Защита живёт у нас, а не у того, к кому подключились.
- **Тарелка структурой.** Инструмент возвращает не только текст, но и машиночитаемый
  объект (structured output) — клиенту не надо разбирать строку.

## Термины простыми словами
- **MCP-сервер** — «ресторан»: программа, у которой есть инструменты для модели.
- **MCP-клиент / агент** — «посетитель»: подключается к серверу и зовёт инструменты.
- **tool (инструмент)** — «блюдо»: одно конкретное действие («найти клиента»).
- **schema (input schema)** — «что уточнить при заказе»: какие поля принимает инструмент,
  какие обязательны, какие допустимые значения.
- **tools/list** — «меню»: список всех инструментов сервера (это читали на Дне 16).
- **tools/call** — «заказ на кухню»: реальный вызов инструмента с аргументами.
- **FastMCP** — высокоуровневая обвязка: вешаешь `@mcp.tool` на функцию, схема входа
  собирается из типов. Встроена в официальный `mcp` SDK.
- **транспорт** — как связаны клиент и сервер: **stdio** (локально, под-процесс) или
  **Streamable HTTP** (по сети). Старый HTTP+SSE — устарел.
- **annotations** — пометки на инструменте: readOnly (только читает) / меняет данные.
  Это подсказки, чужим верить нельзя.
- **tool-calling loop** — цикл: модель выбирает инструмент → агент зовёт → результат
  обратно в модель → она отвечает. Выбор делает модель (tool_choice=auto).
- **человек-в-цикле (human-in-the-loop)** — подтверждение живого человека перед записью.
- **structured output** (outputSchema / structuredContent) — инструмент описывает форму
  результата и возвращает машиночитаемый объект, а не только текст.
- **tool poisoning** — атака: в описание инструмента зашита скрытая команда, модель её
  читает и слушается.
- **prompt injection через результат** — команда спрятана в том, что инструмент ВЕРНУЛ;
  модель читает тарелку вместе с этой запиской и может послушаться.

## Где фронтир / что устаревает (из разведки 27.06)
- **Сегодня:** сервер пишут на FastMCP (`@mcp.tool` + схема из типов), транспорт —
  stdio или Streamable HTTP. Низкоуровневый сервер (ручная JSON-схема) — «продвинутое».
- **Новое за год:** structured output / outputSchema (спека 2025-06-18), tool annotations,
  elicitation (сервер переспрашивает у пользователя), Tool Search и Code Execution with
  MCP (приёмы Anthropic против дороговизны, не часть протокола).
- **Устаревает:** транспорт HTTP+SSE → Streamable HTTP; голый low-level сервер для
  обычных задач. На горизонте слом спецификации (RC 2026-07-28) — поэтому SDK пинят (`mcp<2`).
- **Безопасность (новый пласт):** OWASP MCP Top 10, tool poisoning, rug pull (подмена
  описания после доверия), confused deputy (проброс чужого токена — спека запрещает).
  Практика: человек-в-цикле на запись, не верить чужим ярлыкам, чистить результат тулза.

## Что построили (наше решение)
Python + FastMCP (`mcp` 1.28). Сервер `mcp_server.py` с двумя инструментами вокруг
локальной мини-CRM (`crm.py`): `search_clients` (read) и `create_client` (write). Схема
входа — из type hints + `Field`, регистрация декоратором, результат — Pydantic-модели
(→ outputSchema + structuredContent). Агент `agent.py` на OpenRouter `gpt-oss-120b`:
настоящий tool-calling loop, человек-в-цикле на запись. CLI `task17.py` (+ `--demo`) и
веб-витрина `app.py`/`index.html` с пошаговой анимацией.

Живая находка: `gpt-oss-20b` на `tool_choice=auto` инструмент звать ОТКАЗЫВАЕТСЯ
(молчит), `gpt-oss-120b` — выбирает сам и правильно. «Сам выбрать инструмент» — умение,
которое у мелких моделей ещё хромает.
