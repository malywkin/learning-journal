# День 20 — Оркестрация нескольких MCP-серверов (шпаргалка)

Тема: не один сервер, а **три** (reddit / storage / utils). Агент сам выбирает нужный
инструмент, а **хост** направляет вызов на тот сервер, которому инструмент принадлежит.
Длинный флоу проходит через все три сервера.

Сквозной мост: День 16 — клиент к чужому серверу. День 17 — свой сервер + агент. День 19 —
несколько инструментов цепочкой на ОДНОМ сервере (пайплайн против агента). День 20 —
серверов стало НЕСКОЛЬКО, и добавился новый вопрос: кто направит вызов на нужный сервер.

---

## Что собрано (всё проверено вживую)

- **Три отдельных FastMCP-сервера**, каждый на своём порту, транспорт Streamable HTTP:
  - `reddit_server.py` (:8101) — `search_reddit`, `summarize_posts`. Ходит наружу: reddit.com + LLM.
  - `storage_server.py` (:8102) — `save_note`, `read_note`, `list_notes`. Пишет на локальный диск.
  - `utils_server.py` (:8103) — `now` (часы ОС, **никуда не ходит**), `translate_ru` (зовёт LLM).
- `host.py` — **хост-агент**: держит по клиенту на каждый сервер, склеивает их `tools/list`
  в один список, маршрутизирует вызовы.
- `app.py` + `index.html` — витрина «модель выбрала → хост направил», цвет = сервер.
- `task20.py` — то же из терминала. `run.py` — поднять три сервера + витрину разом.
- `llm.py` — общий доступ к OpenRouter (им пользуются и reddit, и utils).

---

## Три узла (суть, без зубрёжки)

### 1. Один клиент на сервер, единый список с префиксом
Хост открывает **три отдельных соединения** и у каждого спрашивает `tools/list`. Все
инструменты складывает в **один плоский список**. Модель видит просто кнопки и выбирает
по имени — она НЕ знает, что серверов три.

Имена с разных серверов могут совпасть, а неймспейса в самом протоколе MCP **нет** — это
обязанность хоста. Префиксуем `server__tool` (как Claude Code делает `mcp__server__tool`).

### 2. Маршрутизирует ХОСТ, а не модель
Модель сказала «зови `storage__save_note`» — хост сам отрезает префикс `storage__`, находит
нужное соединение и шлёт вызов туда. Это и есть «корректно маршрутизировал запросы» из
задания. Модель выбирает ЧТО; хост решает КУДА.

### 3. Состояние между вызовами протокол не хранит (stateless)
В нашем флоу выход одного шага = вход следующего: посты → английский дайджест → русский
перевод → отметка времени → файл. Протокол это «не помнит» — данные переносит сама модель,
подставляя их в аргументы следующего вызова. Если серверу нужно настоящее состояние, он
отдаёт ярлык (вроде `basket_id`), и модель таскает его дальше.

### Куда «подключается» сервер — важный момент дня
Связь «агент ↔ сервер» — это и есть MCP. А что сервер делает ВНУТРИ (звонит на сайт, лезет
в файл, смотрит на часы) — его личная кухня, агенту не видна. Сервер вовсе **не обязан**
куда-то ходить: `utils__now` читает часы операционной системы и не делает ни одного сетевого
вызова. «Подключается или нет» — свойство конкретного инструмента, а не сервера целиком
(на той же стойке `translate_ru` к LLM ходит, а `now` — нет).

### Проверка из задания
- **Инструменты с разных серверов** — флоу задействовал reddit + utils + storage.
- **Корректность выбора** — нужный инструмент нашёлся на сервере, чьё имя стоит в префиксе.
- **Корректность порядка** — нельзя сохранить раньше, чем перевёл; перевести раньше, чем
  свёл; свести раньше, чем нашёл. Витрина это проверяет и подсвечивает нарушения.

## А как по-взрослому (лестница зрелости)
1. **Не грузить все инструменты вперёд.** Три сервера могут занять десятки тысяч токенов
   ДО первого вопроса. Зрелее — динамический поиск инструментов (Anthropic Tool Search,
   `defer_loading`): модель видит поиск + пару частых, остальное находит по запросу.
2. **Меньше инструментов — лучше выбор.** На больших наборах точность падает (модель путает
   похожие). OpenRouter/OpenAI и практики советуют держать набор узким.
3. **Шлюз-агрегатор (gateway)** при многих серверах: один прокси за единым адресом держит
   маршрутизацию/неймспейсинг/безопасность (Docker MCP Gateway, FastMCP 3.0 mount/proxy).
4. **Безопасность нескольких серверов:** вредный сервер может подсунуть инструмент с именем
   доверенного (shadowing) или спрятать команду в описании (poisoning). По умолчанию MCP
   серверы друг от друга не изолирует — поэтому у нас все три свои и локальные.
