# День 31 — Ассистент разработчика: выжимка (конспект для повторения)

**Беда, которую решаем:** собрать из всего пройденного одного ассистента, который понимает
проект и сам выбирает нужный инструмент под вопрос. Капстоун недели 7.

## Что построили — три инструмента под командой `/help`

Три инструмента легли ровно в §8 конспекта «три вида инструментов»:

| Инструмент | Вид §8 | Что делает | Опора |
|---|---|---|---|
| поиск по докам (`docs_tool.py`) | **RAG Tools** | ищет по документации проекта смыслом | ядро Дней 21–24 |
| MCP-git (`mcp_git.py`) | **MCP Tools** | спрашивает живое состояние репо (ветка/статус/лог/дифф) | каркас Дня 17 |
| чтение файлов (`fs_tool.py`) | **System Tools** | grep/read/list по репо на лету | новьё (фронтир) |

Роутер (`router.py`) сшивает всё в **function-calling цикл** (§10); веб-лицо (`app.py` +
`index.html`) — окно чата со значком «какой инструмент сработал». Запуск двойным кликом
(`Ассистент.command`). Движок **универсальный**: путь к репо + маска доков = настройка
(`config.py`), наводится на любой репозиторий.

## Механика под капотом (главное, что нужно понимать)

1. **Модель сама ничего не делает — она ПРОСИТ.** Возвращает «хочу инструмент X» (это
   `finish_reason=tool_calls`), а выполняет вызов наш код и кладёт результат обратно.
2. **Цикл, а не один заход (tool-use loop, §10):** попросила → выполнили → снова спросили,
   пока модель не ответит словами. Для сложного вопроса — несколько кругов подряд.
3. **Выбор инструмента — по ОПИСАНИЯМ, а не по «уму».** Модель сравнивает вопрос со смыслом
   подписи каждого инструмента (то же сравнение по смыслу, что в RAG). → Рычаг надёжности
   (принцип Anthropic из брифа): **чёткие непересекающиеся описания важнее силы модели.**
4. **Предохранитель (§14):** упёрлись в предел кругов (`MAX_TOOL_HOPS`) — НЕ сдаваться с
   пустыми руками, а заставить модель ответить по уже собранному (`tool_choice` снят).
   Поймали вживую: на составном вопросе модель зацикливалась на `git_log`.

## Тройная сверка (Лекция / Brief / Личное)

- **Лекция (Гладков, §8–§14):** три вида инструментов, function-calling + tool-use loop,
  sandbox опасное/безопасное, Retry→Fallback→Human.
- **Brief (фронтир, 18.07):** для своего репо к 2026 чистый RAG уже не автомат — лидеры ушли
  в агентное чтение файлов; поэтому у нас **гибрид**. `/help` в реальных инструментах не
  «отвечает на вопросы» — это обычный tool-use loop.
- **Личное:** живой пинг токена перед опорой; Contextual Retrieval в эмбеддинги; связка
  поиск→реранкер с Дней 22–23; пойманный и починенный баг §14.

## Зонтик

RAG (память доков) + MCP (руки/живое состояние) + System (глаза/файлы) — это не три темы,
а один механизм «инструмент = описание + функция», а выбор делает модель по описаниям.
Над всеми — один цикл §10. Надёжность держится на ясности описаний, а не на силе модели.

**Модель, провайдер:** DeepSeek основной (tool-calling, проверен вживую 1.6с), локальный
`qwen3.5` (LM Studio) — запасной (§14 fallback).
