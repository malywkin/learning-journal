# День 14 — Инварианты и ограничения состояния

Добавьте в ассистента **инварианты** — то, что он не имеет права нарушать.

**Примеры инвариантов:**
- выбранная архитектура
- принятые технические решения
- ограничения по стеку
- бизнес-правила

**Сделайте так, чтобы:**
- инварианты хранились отдельно от диалога
- ассистент явно учитывал их в рассуждениях
- ассистент отказывался предлагать решения, которые их нарушают

**Проверьте:**
- что происходит при конфликте запроса и инварианта
- как ассистент объясняет отказ

**Результат:** ассистент, работающий в рамках заданных инвариантов.

**Формат:** Видео + Код / Текст

## Уточнения преподавателя (Алексей Гладков, чат курса)

Контекст из обсуждения в чате — учитывать при дизайне (правило `read-course-chat-before-design`):

- **Суть инвариантов:** это подкапотные КОНСТАНТНЫЕ ограничения агента, к которым
  пользователь не имеет отношения. Пользователь может попытаться их обойти, не зная об
  их существовании, — а агент не позволит. Пример Гладкова: ограничиваем мат; юзер
  просит матный анекдот — агент отказывает. (Денис Абрашкин переспросил формулировку,
  Гладков подтвердил: «Всё так».)
- **Задачка со звёздочкой:** дать пользователю самому накидывать себе самозапреты —
  например, по проекту «не пиши на Java».
- **Как проверять конфликт (детерминированно vs LLM):** на вопрос Anastasia A
  («обязательно ли детерминированно — `string.contains` — или лучше запросом в LLM?»)
  Гладков ответил: «Это два разных способа, они друг друга не взаимоисключают. Можешь
  на практике проверить оба способа».
- **Комбинации (Anastasia A):** хардкод запрещённых условий + проверка кодом, ЛИБО
  настройка запрета пользователем + проверка в LLM. Возможен flow «запрет пользователем
  → обработка запрета один раз в LLM → проверка кодом».
- **Взаимопроверка LLM-ками (Гладков):** «Можно ещё взаимопроверку ллмками сделать.
  Например пишущего агента контролируют три разных проверялы, которые ещё и друг с
  другом спорят».

## Связь с Днём 13
Прямое продолжение машины состояний (Дня 13): там были РЕЛЬСЫ разрешённых переходов
(что можно делать), здесь — ИНВАРИАНТЫ (что нельзя НИКОГДА, на любом этапе). Рельсы
ограничивают переходы между этапами; инварианты ограничивают содержание решений.
