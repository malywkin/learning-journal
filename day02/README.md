# День 2 — Формат ответа (контроль через API)

Один и тот же вопрос отправляется в LLM **дважды**: без ограничений и с ограничениями.
Цель — увидеть, как меняется ответ, когда мы управляем форматом, длиной и завершением.

## Запуск
```bash
cp .env.example .env   # вставить ключ OpenRouter (или используется ключ из day01)
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python task2.py
```

## Что под капотом — три рычага контроля

| Рычаг | Где задаётся | Как работает |
|------|--------------|--------------|
| **Формат** | `system`-промпт (словами) | Описываем структуру: «список из 3 пунктов, без вступления». Модель старается следовать. |
| **Длина** | `max_tokens=120` (параметр API) | Жёсткий предел: генерация обрывается на N токенов, даже посреди слова. |
| **Завершение** | `stop=["4.", "Заключение"]` (параметр API) | Как только в выводе появляется такая строка — генерация прекращается, сама строка в ответ НЕ попадает. |

### Два уровня управления
- **Словами в промпте** (намерение): «коротко», «3 пунктами» — модель ограничивает себя сама, ответ выходит цельным.
- **Параметрами API** (механика): `max_tokens`, `stop` — обрывают вывод принудительно, без оглядки на смысл.
- Хорошая практика — **совмещать**: промпт задаёт желаемый вид, `max_tokens` страхует от перерасхода.

### `finish_reason` — почему генерация остановилась
Код печатает это поле, чтобы видеть причину:
- `stop` — модель закончила сама **или** сработала наша `stop`-строка;
- `length` — упёрлись в `max_tokens` (ответ обрезан принудительно).

## Заметки по версиям API (актуально на 06.2026)
- `max_tokens` — устаревающее имя; новое — `max_completion_tokens`. Для не-reasoning
  моделей `max_tokens` ещё работает как алиас (nemotron — не o-series, подходит любое).
- `stop` — до 4 последовательностей; стоп-строка в ответ не включается.
- Для строгого формата есть `response_format` (`json_object` / `json_schema`,
  Structured Outputs) — это «следующий уровень» формата, его берём в более поздних днях.
