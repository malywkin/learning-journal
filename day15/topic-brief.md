# topic-brief — День 15: контролируемые переходы + рой агентов + валидация-ворота (2026)

Разведка фронтира роем агентов (17 агентов, 58 находок, 14 на адверсариальный фактчек).
Дата: 21.06.2026. Это разведка «на слом», не подтверждающий поиск.

## Как работает сегодня
- **Конечный автомат для агента НЕ устарел** — живой канон: StateFlow (моделирует процесс
  как машину состояний, +13–28% к ReAct при 3–5× меньшей цене), UFO3 (FSM-слой на жизненный
  цикл агента, ноя-2025), MetaAgent (автогенерация мультиагентной системы на FSM).
  → arxiv.org/html/2511.11332v1 ; arxiv.org/html/2403.11322v1
- **Канон «ворот» на переходе в LangGraph 1.0** (GA 22.10.2025): динамический `interrupt()`
  внутри узла + возобновление `Command(resume=value)` (значение из Command становится
  результатом `interrupt()`). Статические `interrupt_before/after` официально «НЕ для
  human-in-the-loop, только для отладки». Обязателен checkpointer (персист состояния) — у
  нас это `state.json`. → docs.langchain.com/oss/python/langgraph/interrupts
- **Подводный камень resume:** `interrupt()` перезапускает ВЕСЬ узел с начала — код до точки
  паузы выполняется заново. Побочные эффекты до `interrupt` должны быть идемпотентны. То же
  у Temporal (переигрывает воркфлоу с начала, кэшируя только результаты внешних вызовов).
  → ПРЯМОЙ урок для нашей паузы: на resume НЕ дёргать LLM повторно — поднять состояние с
  диска и продолжить.
- **OpenAI handoff = переход с валидацией:** `input_type` (Pydantic-схема) проверяется КОДОМ
  локально, и только потом управление уходит дальше. Гейт: `is_enabled`, `on_handoff`
  (callback-предусловие), `input_filter`. → openai.github.io/openai-agents-python/handoffs/

## 🆕 Новое за год
- **Слоистый каскад ворот:** сперва дешёвая ДЕТЕРМИНИРОВАННАЯ проверка (regex/схема/«артефакт
  есть»/компиляция — «самый высокосигнальный гейт для агентов»), и лишь то, что код решить не
  может, отдают LLM-судье. Чистый LLM-гейт там, где хватает кода, — антипаттерн.
  → futureagi.com/blog/deterministic-llm-evaluation-metrics-2026
- **Панель из РАЗНЫХ моделей вместо одного судьи (PoLL, Cohere 2024):** несколько меньших
  моделей из РАЗНЫХ семейств бьют одного большого судью, дают меньше внутреннего перекоса и
  в 7× дешевле. + перестановка позиций (вердикт судьи плывёт от порядка ответов).
  → arxiv.org/html/2404.18796
- **OpenAI Agents SDK guardrails:** tripwire HALTS выполнение. Детерминированный-vs-LLM гейт
  подан как экономика: дешёвый детерминированный режет до запуска дорогой модели.
- **A2A (Agent2Agent)** ушёл в Linux Foundation (23.06.2025), 150+ компаний, IBM ACP слит
  внутрь — складывается единый кросс-вендорный стандарт связи агентов.

## ⚠️ Спорное / самое важное для нас
- **Рой-голосование опасен — хуже всего в ПРАВЕ.** AWS/HSBC: из спорных вопросов 23.9%
  сходятся к ЕДИНОГЛАСНО НЕВЕРНОМу ответу к 3-му раунду; по доменам — право 34.8%,
  психология 33.3%, математика 12.1%. Причина: RLHF-угодливость → голоса скоррелированы,
  не независимы → большинство даёт ложную уверенность. Больше раундов спора = ХУЖЕ.
  Фикс: слой, который ВОЗДЕРЖИВАЕТСЯ и эскалирует к человеку (перехватывает ~82% ложного
  единогласия). → arxiv.org/html/2604.07667 ; arxiv.org/abs/2509.23055
- **LLM-судья ненадёжен:** self-preference (судит свои генерации мягче, NeurIPS 2024),
  позиционный перекос (систематичен, не шум), на сложных бенчмарках фронтир-модели >50%
  ошибок. → arxiv.org/abs/2410.21819 ; adaline.ai/blog/llm-as-a-judge-reliability-bias
- **Мультиагент = ~15× токенов** против чата (Anthropic), обгоняет одиночный агент на 90.2%,
  НО 80% разброса объясняется просто числом токенов. ЧЕСТНО: это самоотчёт Anthropic на их
  же бенчмарке, независимо не воспроизведён (я — модель Anthropic, называю прямо).
  → anthropic.com/engineering/multi-agent-research-system
- **Когда рой ВООБЩЕ оправдан** (консенсус 2026): работа чисто декомпозируется ИЛИ подзадачи
  нужны разные инструменты/модели ИЛИ нужны явные границы для аудита/безопасности. На
  линейном конвейере и простом чате рой 5–10× удорожает без прироста точности. Cognition
  «Don't Build Multi-Agents»: писатель ОДИН (single-threaded writes), лишние агенты — только
  read-only интеллект. → cognition.com/blog/dont-build-multi-agents

## Что из этого берём в День 15
1. Машина состояний — оставляем (канон жив).
2. Ворота-каскад: детерминированный пол (план одобрен / черновик есть / вердикт PASS) +
   смысловой вопрос панели только где код не решает.
3. Рой «по-взрослому»: разные линзы, read-only, ОДИН писатель-оркестратор; правило «нужны
   ВСЕ ворота», а не большинство; расходятся/не уверены → воздержаться → человек (пауза 13).
4. Инварианты Дня 14 — глобальные ворота на выход агента.
5. Рядом — живая демонстрация ловушки: наивный кворум одинаковых моделей штампует неверный
   юридический ответ, правильная схема ловит.
6. Resume не повторяет работу: поднимаем состояние с диска, готовые артефакты не
   переделываем (урок идемпотентности).
