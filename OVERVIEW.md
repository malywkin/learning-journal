# learning-journal — обзор проекта

Учебный журнал 7-недельного курса по ИИ (AI Advent Challenge 8). Публичный репозиторий
с решениями заданий: 35 учебных дней по будням, каждый день — новое задание, код решения
и выводы. Ниже — карта проекта для быстрого понимания структуры (точка входа для
ассистента-разработчика: что где лежит и по каким правилам).

## Что это за проект

- **Цель:** пройти курс по прикладному ИИ, собирая каждый день работающее решение и
  разбор «что под капотом». Не разовые скрипты, а нарастающая база: каждый день строится
  на пройденном, код и приёмы переиспользуются между днями.
- **Язык:** Python. Общение по проекту — на русском.
- **LLM API:** основной шлюз — OpenRouter (OpenAI-совместимый, `base_url`
  `https://openrouter.ai/api/v1`, пакет `openai`, ключ `OPENROUTER_API_KEY`; модели
  `gpt-oss` 20B/120B, `gemma`). С Дня 24 для заданий с tool-calling используется DeepSeek
  (`https://api.deepseek.com`, `deepseek-chat`) — стабильнее, без 429. С Дней 26–30 —
  локальная модель `qwen3.5` через LM Studio (`http://localhost:1234/v1`) как запасной путь.

## Структура папок

- `dayNN/` — папка одного учебного дня (с ведущим нулём: `day01`…`day35`, чтобы
  сортировались). Внутри:
  - `task.md` — формулировка задания (от преподавателя Алексея Гладкова).
  - `taskN.py` — главный файл решения (`task1.py`, `task2.py`, …).
  - `requirements.txt`, `.env` — зависимости и секреты дня (`.env` НИКОГДА не коммитится).
  - `takeaways.md` — выводы дня: что построили, какие приёмы/код переиспользуемы дальше.
  - Часто есть веб-демо (`app.py` на FastAPI + `index.html`) — «стеклянный ящик», где
    видно, что происходит под капотом.
- `.gitignore` — что не уходит в публичный репозиторий: секреты (`.env`, `*.key`),
  виртуальные окружения (`.venv/`), базы данных и индексы (`*.db`, `*.sqlite`), видео,
  тексты под копирайтом (корпуса книг), приватные логи и данные прогонов.

## Соглашения проекта

- **Имена:** папки дней — с ведущим нулём (`day07`, не `day7`); главный файл решения —
  `taskN.py` без нуля (`task7.py`).
- **Секреты** только в `.env` (в `.gitignore`), в коде — через переменные окружения,
  никогда не хардкодятся.
- **Изоляция:** тяжёлые задания держат свой `.venv` в папке дня; лёгкие переиспользуют
  окружение соседнего дня.
- **README внутри `dayNN/` не создаём и не пушим** — по договорённости курса.
- **Принцип «не с нуля»:** новое задание сначала сверяется с прошлыми днями — что уже
  построено и переиспользуемо (ядро RAG, каркас MCP, чат-сессия и т.п.).

## Технические вехи по неделям

- **Неделя 1 (Дни 1–5):** первые вызовы LLM, промптинг, структурированный вывод (JSON).
- **Неделя 2 (Дни 6–10):** контекст, история диалога, управление контекстным окном.
- **Неделя 3 (Дни 11–15):** агенты, инварианты/самозапреты, планирование задач.
- **Неделя 4 (Дни 16–20):** MCP — клиент и свой сервер (FastMCP), инструменты как функции,
  локальные сервисы (CRM, хранилище заметок, планировщик).
- **Неделя 5 (Дни 21–25):** RAG — индекс (sqlite-vec + эмбеддер bge-m3), поиск, реранкер
  (cross-encoder), цитаты и анти-галлюцинации (порог + проверка цитат + LLM-судья).
- **Неделя 6 (Дни 26–30):** локальные модели — квантизация, запуск через LM Studio,
  локальная LLM как приватный сетевой сервис (reverse-proxy привратник).
- **Неделя 7 (Дни 31–35, капстоун):** сборка пайплайнов — субагенты, инструменты,
  автоматизация. День 31 — ассистент разработчика (этот движок): RAG по докам + MCP-git +
  агентное чтение файлов под командой `/help`.

## Ключевые переиспользуемые модули

- `day21/` — построение векторного индекса (sqlite-vec, эмбеддер bge-m3).
- `day22/rag_core.py` — ядро RAG-запроса: `retrieve()`, `build_context()`, `rag_answer()`.
- `day23/rerank.py` — реранкер (cross-encoder), score 0..1 + порог.
- `day24/grounded.py` — ответ с цитатами: контракт `{answer, sources, quotes}`,
  проверка цитат кодом, порог-отказ, LLM-судья; переключение провайдера DeepSeek/OpenRouter.
- `day25/chat.py` — чат-сессия поверх RAG (память диалога).
- `day17/mcp_server.py` — каркас MCP-сервера на FastMCP (`@mcp.tool` на обычной функции).
